# ScrollFerry · 舷渡 技术说明

适用版本：v2.1.3。本文面向开发、打包及维护人员；日常操作见 [使用说明](user-guide.md)。

## 1. 整体架构

软件采用本地 Python 桌面架构：Tk 显示 PDF 和编辑区域，PDF 工具提取文字及渲染页面，导出器生成截图和清单，Playwright 操作小鹅通后台。当前不依赖自建服务器，不包含钉钉登录验证。

```text
PDF → 文字与版面分析 → 题目工程 → 人工校对 → 图片及 manifest.json
                                                   ↓
本机上传回执 ← 保存结果 ← 小鹅通题库 ← 素材分组与图片上传
```

| 模块 | 职责 |
| --- | --- |
| `scrollferry/app.py` | Tk 界面、校对编辑、撤销重做、进度窗口、上传入口 |
| `scrollferry/core.py` | PDF 读取、基础识别、截图渲染、工程与批次导出 |
| `scrollferry/layout.py` | 结构化版面识别、题目与答案区域对应、跨页拆分 |
| `scrollferry/separate.py` | 分卷按题号匹配、共用材料及写作题识别、公式图片边界 |
| `scrollferry/upload.py` | 上传校验、图片命名、队列、状态保存与恢复 |
| `scrollferry/xiaoe.py` | 小鹅通页面定位、素材操作、题目填写及保存 |
| `scrollferry/browsers.py` | Chrome / Edge 优先级和启动回退 |
| `scrollferry/paths.py` | 用户数据目录、批次运行目录及资源路径 |
| `packaging/`、`ScrollFerry.spec` | 打包入口、构建脚本、安装程序配置 |

主要依赖为 pdfplumber、pypdfium2、Pillow 和 Playwright。基础依赖在 `requirements.txt`，浏览器上传依赖在 `requirements-upload.txt`。安装包使用 PyInstaller 和 Inno Setup。

## 2. PDF 识别与截图

pdfplumber 读取文字层和字符位置，优先调用结构化版面识别，再使用基础规则作为补充。题号、章节、选项标记及答案标记用于确定区域；这些是规则识别，不是通用 OCR 或大模型识别。

区域使用 PDF 页面坐标，矩形表达为 `[left, top, right, bottom]`，页码在内部从 0 开始。显示缩放只影响界面，保存的坐标仍对应 PDF。截图资产可以包含多个区域，导出时按区域顺序纵向拼接，支持跨页答案和解析。

pypdfium2 渲染原页面，Pillow 完成白色遮盖、裁切、留边和拼接。默认截图渲染比例为 2，裁切后增加白色边缘。涂白记录独立于 PDF，不修改源文件；“解析”文字保留，主要遮盖题号和选项标号。

选择题支持连续的 A–H 选项，同行选项需要分别划分区域。复杂表格、双栏或不规则题号仍可能识别错误，应通过样本回归调整规则，不能仅以成功导出判断拆题正确。

## 3. 工程和导出数据

工程保存源 PDF 路径、题目、答案、校对状态、识别提示及各截图区域。源 PDF 不嵌入工程，移动源文件会影响后续读取。题型包括单选、多选、填空、解答及未确定类型；截图类型包括题干、选项、答案原图和解析。

分卷工程为 version 4，额外保存 `answer_source` 和 `question_page_count`。区域页码在两卷拼接后的虚拟页序中连续编号；`render_page(project, page)` 将后半段映射到解析 PDF，编辑、预览与导出使用同一映射。旧单卷工程仍然有效。共用题干在各题中保存独立区域副本；写作题使用 `solution` 类型及 `subtype` 标记，不虚构文字答案。解析内部的数字条目不作为新题号，通过 section 与 original_number 配对，允许不同题型重新编号；同一分区的重复题号仍不自动配对。

396 分卷样本回归可设置 `SCROLLFERRY_SEPARATE_QUESTIONS` 与 `SCROLLFERRY_SEPARATE_ANSWERS`，再执行完整单元测试。样本 PDF 和生成图片不提交到仓库。

导出批次包含以下文件：

| 文件 | 内容及用途 |
| --- | --- |
| `batch.json` | 试卷名称、批次前缀和素材分组信息 |
| `project.json` | 导出时的工程快照，用于继续校对 |
| `manifest.json` | 上传所需的题目、答案及图片对应关系 |
| `warnings.json` | 识别及校对提示 |
| `status.json` | 导出过程状态；上传要求导出已完成 |
| `*.png` | 各题的截图资产 |

GUI 在用户选择的父目录下建立唯一子目录，因此父目录无需为空。底层导出器仍要求目标批次目录为空，防止混入旧图片。

图片名称示例：`六月数学_a1b2c3d4_Q0001_02_option_A.png`。前缀由清理后的试卷名和随机批次编号组成。命名处理会移除不适合文件名的字符，并按 UTF-16 长度限制试卷名，为小鹅通分类名称长度预留空间。题库分类与素材分组使用同一前缀。

修改工程后重新导出会产生新批次。它不表示更新小鹅通中的原题，也不会继承旧批次的全部保存结果。

## 4. 上传执行与断点恢复

### 校验与准备

上传前检查导出状态、题号唯一性、资产类型、图片存在性及路径合法性，防止清单引用批次外的文件。上传队列通过清单与图片内容摘要识别变化；已发生变化的内容不能直接沿用旧回执。

选择题要求连续选项和有效答案字母。填空题按问答题上传，优先使用答案原图，其次文字答案；解答题再允许使用完整解析图作为答案。有效答案原图可以替代填空题公式的文字识别，但不会自动豁免其他识别问题。

### 执行顺序

1. 启动软件专用浏览器资料目录，等待用户登录小鹅通。
2. 建立或查找同名素材分组，按完整名称检查图片，分批上传缺失素材。
3. 建立或查找同名题库分类。
4. 将未保存且通过校验的题目队列倒序，逐题填写。
5. 根据实际选项数量调整输入框，通过完整图片名搜索素材并插入。
6. 点击保存并确认返回题库列表，再记录该题已保存。

每批素材最多 100 张。“试传下一题”的数量限制仅作用于题目，整卷素材仍先上传。倒序依据清单顺序，不按后台已有题目重新排序。

### 状态与不确定结果

| 对象 | 主要状态 |
| --- | --- |
| 图片 | `pending`、`submitting`、`uploaded` |
| 题目 | `pending`、`blocked`、`submitting`、`saved` |
| 批次 | `prepared`、`materials_uploaded`、`partial`、`completed`、`paused` |

提交动作前先记录 `submitting`，确认完成后再改为成功状态。网络中断或页面超时可能造成“后台已成功，本地未确认”，因此恢复时不会盲目重试不确定的题目保存。只有确定文件选择尚未开始的失败，才能按未上传安全重试。

队列以临时文件写入后替换的方式保存，减少写入中断导致的损坏。该机制不是跨进程锁，不应同时运行两个实例处理同一批次。当前也没有面向用户的手动核销不确定回执界面。

## 5. 数据目录和浏览器兼容

| 平台 | 默认运行数据目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\ScrollFerry` |
| macOS | `~/Library/Application Support/ScrollFerry` |

开发和测试可通过 `SCROLLFERRY_DATA_DIR` 覆盖运行目录。运行数据主要包括：

- `browser-profiles/chrome`、`browser-profiles/msedge`：独立浏览器登录资料。
- `batches/<批次路径摘要>/upload-queue.json`：上传状态。
- 批次运行目录中的 `upload-assets`：用于上传的图片副本。
- `upload-error.png`、`upload-error.json`：失败现场和诊断信息。

批次运行目录由导出目录的绝对路径计算，因此移动导出目录可能找不到原回执。迁移电脑时，仅复制截图不足以恢复全部进度。旧版导出目录中的队列可迁移到用户目录并保留旧文件，但旧队列格式不一定能直接执行新版上传流程。

Windows 读取 HTTPS 默认浏览器设置：默认是 Chrome 或 Edge 时优先尝试，否则按 Chrome、Edge 顺序启动。失败后尝试另一种浏览器。macOS 当前按 Chrome、Edge 顺序尝试。软件不会修改系统默认浏览器，安装包也不包含浏览器本体。

两个浏览器使用不同资料目录，不共享软件登录状态，也不接管用户日常浏览器资料。维护时不要将登录资料、试卷、导出图片或上传诊断提交到公开仓库。

## 6. GUI 与后台任务

耗时处理放入后台线程，通过队列将进度和结果传回 Tk 主线程。弹窗根据主窗口位置居中；处理期间显示阶段进度，并通过取消事件在后续检查点停止任务。

取消不是强制终止浏览器调用，也不撤销已经上传的图片或保存的题目。若当前调用正在等待页面，取消需要等该步骤返回。

编辑撤销使用工程快照，最多保留 50 次，重新加载工程后重置。撤销历史不写入工程文件。上传时使用导出的清单，而不是尚未导出的界面修改。

## 7. 开发、测试与打包

推荐 Python 3.12，并确保带 Tcl/Tk。在虚拟环境中执行：

```bash
python -m pip install -r requirements.txt -r requirements-upload.txt reportlab
python -m unittest discover -s tests -v
python -m scrollferry.app
```

| 测试文件 | 覆盖重点 |
| --- | --- |
| `tests/test_core.py` | PDF 识别、遮盖、导出、五选项和同行选项 |
| `tests/test_desktop.py` | 用户目录、浏览器回退和旧回执迁移 |
| `tests/test_upload.py` | 校验、倒序、答案图片、恢复及不确定提交 |
| `tests/test_real_paper.py` | 实际试卷的题型、选项和跨页解析 |

实际试卷测试需设置 `SCROLLFERRY_TEST_PDF` 指向本机样本，未设置时跳过。普通测试使用生成样本及替身，不会登录小鹅通或创建真实题目；它们不能代替后台页面实测。

GitHub Actions 的 `Build Windows installer` 由手动触发，在 Windows runner 上安装依赖、运行测试、执行 PyInstaller 和 Inno Setup。随后静默安装到含空格的路径，运行打包程序的 `--smoke-test`，检查 Tk、图标、PDF 渲染组件及浏览器相关依赖。该检查不验证小鹅通业务流程。

全部通过后上传安装包附件，保留 14 天；目前不自动发布 GitHub Release。具体命令见 [Windows 打包说明](windows-packaging.md)。Mac 上的单元测试通过不代表 Windows 安装包已经通过验收，应查看对应 Actions 运行结果。

## 8. 维护注意点

- 后台改版导致元素定位失败时，优先检查 `xiaoe.py` 和错误截图。应保留完整文件名匹配、插入结果检查及保存回执机制，避免通过忽略超时来继续上传。
- 新增版面规则时，增加能体现真实错切问题的样本回归，检查公式边界和选项数量。
- 修改清单或队列格式时，明确旧版本迁移方式，尤其不能清空已保存记录后自动重试。
- Windows 路径代码应仅在环境变量缺失时计算主目录回退值，避免测试环境没有主目录变量时提前触发异常。
- Actions 的运行时弃用提醒与实际失败应分开判断；定位失败步骤中最早的具体异常，再检查安装包是否实际生成。

## 2.1.3 实现补充

- `separate.py` 负责分卷分区匹配和页眉页脚边界；`theme.py` 统一界面样式。
- `progress.py`、`progress_button.py`、`ferry_animation.py` 提供任务状态、完成操作和可停止的场景动画。
- 连续 PDF 视图只渲染可见页，同页选题复用图片并更新独立选框层；Tk 9 的 `TouchpadScroll` 单独解码双轴位移。
- 编辑器 `EditorNotReady` 仅在保存前重开表单，最多重试两次。分组创建未确认记录 `group_status=unconfirmed`，恢复时只查找、不重复创建。
- 导出完成的上传入口先执行导出成功回调，再打开上传面板，使用本次批次。
